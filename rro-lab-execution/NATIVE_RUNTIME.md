# Installed primitive field path

`native_engine.Core` is a literal ML-I finite primitive graph. Encoded field-code
fetch, opcode and selector trees, local arity guards, operand latches, retained
old PC and separate continuation assignment execute on the relocated target.
After each commit, a native bit-read/test gate loops while waiting is set;
individual native stepping cannot fetch another field operation before resume.
The native graph supplies the existing generic LAB, conversion and decoder
consumers. Graph locations encode bounded positions; arbitrary generic B
programs, input chains and reserves use actual references.

`native_install.Installer` traverses retained literal source descriptors. Its
first pass allocates, receives grants, initializes and copies every target bit;
its second pass relocates every actual reference through backed forward links.
A final actual forward read and control write deliver the installed entry;
execution reuses that retained control location.
`native_bits.c` executes actual linked primitive vertices, three per bit. Batch
execution retains the same state and target buffers as single-step execution.
Source, pending grants, target directory and the complete source/target overlap
remain in the census. The selected input is the full uncompressed public image;
gzip is source preparation outside this conditional ML-I installation.

The initial granted installer graph is ML-I's supplied finite primitive control;
its complete material is retained and counted. Independent instances may reuse
immutable wiring, with a separately supplied and counted state header whose
source/target/cursor bindings are initially null. Initial control vertices and
both initializer headers have actual retained grant fields. Shared-job union accounting
remains outside these independent component fixtures. The later field interpreter,
decoder, driver and controller material is copied chronologically. There is no
claim that bare P/S creates the initial field/control rights or a physical boot
mechanism. Source preparation, Python/C runtime internals and host compilation
are not recast as mathematical primitives of a different device.

Run with Python 3.12 or newer, assertions enabled, and `cc` available:

```sh
python3 -B rro-lab-execution/native_checks.py --full --output rro-lab-execution/native-results.json
python3 -B rro-lab-execution/native_checks.py --mutation omit-installation-read
python3 -B rro-lab-execution/native_checks.py --mutation omit-native-operation
python3 -B rro-lab-execution/native_checks.py --mutation omit-installation-source-step
```

The mutations must exit nonzero with `installation_bit_read_census` and
`native_operation_census`, respectively. Skipping a real initializer read
vertex must fail with `installation_source_operation` on the actual target bit. Results include actual expensive runs;
finite checks corroborate the all-family ordinary proofs in RRO §§18–20.
The original exact suite and both original strict omissions remain. No complete
received-command parser, original-port session, receipt/cache service, shared-job
allocator/cleanup or full simultaneous evaluator/session account is supplied.
`B_complete` and `C_released` remain false. No new Lean or physical claim is made.
