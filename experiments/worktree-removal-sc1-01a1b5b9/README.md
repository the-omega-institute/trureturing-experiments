# Bounded worktree removal verification

Run `python3 -B verify.py --source /absolute/path/to/saved/implementation/worktree` on macOS with Python 3.12 or later. The program creates only owned dummy Git repositories under the supplied parent (default `/Users/auricstudio`), checks same-filesystem placement, and removes its fixtures before returning. It reads only `git ls-tree` metadata from the pinned project manifest; dummy commits contain no project source or cache copy.

The experiment checks actual payload SIGINT and ordinary qualified retry, actual final-native immutable-pointer failure and orphan refusal, and representative payload-first removal under the unchanged 300-second bound. The representative namespace uses 393567 exact manifest paths, 6793 directories and maximum fanout 147197, with exact logical file sizes and synthetic first-block bytes. Larger files have punched holes; eight manifest symlinks use regular-file stand-ins. An additional `.lake` symlink targets an owned external sentinel. Every file is checked after close. Before every write, the bound includes all prior allocated blocks, full allocation of the next file and a 16 MiB allowance for dummy Git overhead. The bound is 2 GiB of live regular-file `st_blocks * 512`; filesystem-internal metadata and other users' shared-volume allocation are outside this measure.

`result.json` contains the saved source binding, exact input census, native exits, wall and child CPU measurements, final state, retained dummy refs and limitations. CPU deltas use process child-resource accounting around synchronously joined commands. The program rejects success unless payload and native registration are gone, branch OIDs and the external target remain, and source binding is unchanged. One candidate run under shared-host conditions establishes that run only; no historical storage diagnosis, general speed ratio or all-workload deadline guarantee follows. No old-code performance benchmark is repeated.
